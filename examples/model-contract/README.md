# 单一模型类型示例

`BusinessModel` 直接定义于 [库源码](../../src/business-model.ts)，从 `@zerp/ui/model` 导出。节点采用字段、对象、集合的判别联合；业务成员名开放，操作语义固定。库类型不依赖示例对象，不从 `typeof exampleModel` 推导，也不依赖 Vue。

```ts
import { modelMetadata, type BusinessModel } from "@zerp/ui/model";
```

`modelMetadata` 是元数据 Symbol，不占用业务字段名。`BusinessModel` 是唯一公开模型契约，内部节点类型不另行导出。

## 示例对象

[model.type-example.ts](model.type-example.ts) 是只参加 TypeScript 检查的对象字面量。它通过 `satisfies BusinessModel` 验证结构，声明的回调仅展示签名，没有实现，不可作为运行中的应用导入。

示例包含“往来资料”聚合，其成员依次为说明、客户集合和变更记录集合。客户集合有一条选中记录，展示文本、十进制、布尔字段和读取／保存／删除操作；变更记录集合为空，展示空集合仍能提供完整字段结构。

集合的 `element` 直接引用记录模型，提供字段、名称和可用操作；`list` 只表达有序字段投影，不复制字段定义。本例客户集合复用同一个客户节点提供结构和样例数据；空的变更记录集合通过独立元素模型提供字段。UI 不从第一页数据猜测列定义。

示例没有合成后端、Vue 包装、身份索引、草稿同步或请求状态机。业务回调实现及模型如何响应实际后端结果由消费者提供；具体运行实现后续跟随宿主迁移验收。

## 对应 UI 结构

完整结构、字段、按钮和模型来源见 [ui-structure.md](ui-structure.md)。这是该对象应产生的结构示意，不是可配置布局，也不是当前宿主的渲染证据。

目标接入形式仍只有：

```vue
<BusinessApplication :model="model" />
```

UI 根据模型结构及投影生成导航、聚合 Tab、列表、详情和操作区，不要求消费者提供组件、页面工厂、Tab 配置或模板。

## 投影规则

- 只有 `navigationProjection` 引用的节点进入全局导航；本例只有“业务 → 往来资料”，子集合不提升为全局入口。
- 对象按 `form` 顺序组织内容，未提供时按成员声明顺序；`history` 与其他节点使用相同规则。
- 集合按 `element` 和 `list` 生成列，按 `query` 生成查询字段；`items`、分页、`selected` 和 `draft` 表达当前数据及选择。
- 具体节点声明的有限操作投影成对应 UI；权限裁剪可见、可编辑和操作可用性，后端执行真实授权。管理员也不能覆盖业务只读或 `disabledReason`。
- 实际运行时输入直接更新字段 `value`；记录按稳定身份保持节点引用，后端结果更新原节点。切换不自动查询、保存或清空输入，不新增基线、冻结请求和离开确认。

当前类型范围为普通对象和集合。认证、引用、值数组、单据、流程和批次后续纳入同一契约。现有 `BusinessApplication` 尚未迁移，正式范围与阶段证据见 [#152](https://github.com/hansonyu183/zerp-ui/issues/152)。

## 响应式检查

`pnpm test:reactivity` 使用独立的合成测试模型，检查直接输入与后端结果更新、稳定节点引用、Symbol 元数据与结构／权限变化，以及导航切换保留查询、分页、选择和新记录输入。该检查由 CI 的 `check:release` 强制执行，失败会阻断发布检查；普通测试阶段不重复运行它。纯类型示例不参与执行。这些是模型契约检查，不是尚未迁移宿主的 UI 验收。
