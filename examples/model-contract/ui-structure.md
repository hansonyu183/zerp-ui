# 示例对象对应的 UI 结构

来源为 [model.type-example.ts](model.type-example.ts)。以下描述该类型示例的目标投影，没有实现新的 UI，也不作为实际渲染验收。名称与顺序均来自模型；库只掌握固定交互语义。

## 应用与聚合页面

```text
BusinessApplication
├─ 应用外壳
│  └─ 品牌：合成示例 / 示例企业
├─ 全局导航
│  └─ 业务
│     └─ 往来资料                         ← navigationProjection
├─ 统一消息区
│  └─ 这是类型示例。
└─ 聚合页面：往来资料                     ← navigation.current = directory
   ├─ Tab：说明                           ← form[0] → overview
   │  └─ 说明（只读）
   │     输入直接绑定模型，业务操作由消费者提供。
   ├─ Tab：客户                           ← form[1] → customers
   │  ├─ 查询条件：关键词
   │  ├─ 集合操作：查询 / 新增
   │  ├─ 列表：编号 / 名称 / 额度 / 启用
   │  ├─ 分页
   │  └─ 客户资料（当前选中记录）
   │     ├─ 对象操作：读取 / 保存 / 删除（禁用）
   │     └─ 字段：编号 / 名称 / 额度 / 启用
   └─ Tab：变更记录                       ← form[2] → history
      ├─ 集合操作：查询
      ├─ 列表：编号 / 内容
      └─ 空态：暂无记录
```

进入“往来资料”时保留聚合标题和 Tab，默认展示首个可见 Tab“说明”。只切换聚合内的显示内容，不把导航目标改为第一个集合。树中列出所有 Tab 内容，实际只显示当前 Tab。

## 客户 Tab

```text
往来资料
[说明] [客户 ●] [变更记录]

关键词 [                         ]    [查询] [新增]

┌────────┬──────────────┬──────────┬────────┐
│ 编号   │ 名称         │ 额度     │ 启用   │
├────────┼──────────────┼──────────┼────────┤
│ C1     │ 合成客户甲   │ 100.00   │ 是     │
└────────┴──────────────┴──────────┴────────┘
第 1 页 · 每页 20 条 · 共 1 条

客户资料                              [读取] [保存] [删除：禁用]
编号    C1                            （只读）
名称    [合成客户甲                  ] （必填）
额度    [100.00                      ]
启用    [✓]
```

| 区域             | 模型来源                                                   |
| ---------------- | ---------------------------------------------------------- |
| 查询输入         | `customers.query.keyword.value` 及其字段元数据             |
| 查询／新增       | 客户集合的 `operations.query/create`                       |
| 列的名称、值类型 | `customers` 的 `element` 各字段元数据                      |
| 列顺序           | 客户集合的 `list`                                          |
| 行数据           | `customers.items`                                          |
| 分页             | `page/pageSize/total`                                      |
| 详情对象         | `customers.selected`，本例指向 `customer`                  |
| 详情字段顺序     | 客户对象的 `form`                                          |
| 读取／保存／删除 | 客户对象的 `operations.get/update/delete`                  |
| 删除禁用原因     | `operations.delete.disabledReason`：“该记录当前不可删除。” |

示例没有声明导出或核实操作，因此不出现对应按钮。聚合对象没有保存操作，因此也没有覆盖所有 Tab 的共同保存按钮。新增后的记录由 `draft` 表达，保存属于该记录自身的写入边界；本文件不实现回调流程。

详情直达仍以该记录节点为目标，由消费者 Router 端口接驳；宿主保留所属聚合上下文并显示客户内容，不增加客户集合或单条记录的全局导航入口。本例只声明 `href/visit` 的类型，不实现 URL 或 Router。

## 空的变更记录 Tab

```text
往来资料
[说明] [客户] [变更记录 ●]

[查询]
┌────────┬────────────────────────────────┐
│ 编号   │ 内容                           │
├────────┴────────────────────────────────┤
│ 暂无记录                               │
└─────────────────────────────────────────┘
```

`history.items` 为空，但其 `element` 已定义“编号”和“内容”，所以列结构无需等待查询结果。查询条件对象没有字段，UI 不生成空白查询表单；元素模型只读且没有维护操作，UI 不显示保存、删除或新增。

## 响应式变化与权限

模型更新聚合 `form` 后，Tab 按新的投影组织；修改节点名称后，标题和 Tab 名称更新；从投影移除 `history` 后，该 Tab 消失，其他可见内容仍遵循模型顺序。UI 不按业务名称增加例外。

本例为管理员快照，展示完整授权范围；编号仍只读、删除仍因业务原因禁用。普通用户的根级权限事实用于裁剪入口、Tab、字段与操作；权限未就绪时不显示受保护内容。权限不产生模型没有声明的操作，也不代替后端授权。
