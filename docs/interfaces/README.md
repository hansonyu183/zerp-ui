# 静态响应式业务模型接口

正式决定及实施状态维护于 [#152](https://github.com/hansonyu183/zerp-ui/issues/152)。本目录说明静态模型接口及其修订。唯一类型声明源为 src/model/business-model.ts，经 @zerp/ui/model 导出。有序成员和所属明细修订自 0.48.0 起适用。

- [完整类型](../../src/model/business-model.ts)：固定普通属性、字段、统一对象、所属明细、独立集合、领域分组、打印、权限、工作台及应用生命周期。
- [完整合成对象](../../examples/model-contract/static-application.type-example.ts)：直接定义客户、AA、AB、子明细、引用、格式、模板、工作台及完整匿名应用。
- [类型验收](../../examples/model-contract/static-application.type-test.ts)：拒绝旧属性、错误值和错误操作层级，只参加编译。

model 入口仅导出类型，没有 Vue/Vuetify/CSS 运行时依赖。完整静态示例只参加编译，不作为可运行应用导入；可运行的合成消费者位于 examples/model。下述行为的验收以 #159 及关联工单的确切提交、公开入口与独立安装证据为准，类型编译本身不证明行为。

## 应用、认证与工作区

`App` 接收同一个响应式 `BusinessModel`。应用级品牌、主题、会话和消息留在根上。`authentication` 持有登录表单及 `operations.signIn`。`work` 持有业务成员、账户和可选首页集合。登录页使用固定模板，从认证表单的直接成员分别读取第一个单选引用、文本和密码字段，对应账套、账号和密码。工作页接收工作区节点与共用呈现属性。匿名使用登录页，就绪与强制改密使用工作页。

`App` 在宿主 Vue 应用内统一安装 Vuetify。消费者导入 `@zerp/ui/style.css` 并提供模型。可选的 `brand.primary` 和 `brand.secondary` 指定品牌色，更新这些值时主题随模型响应。主题预设和明暗选择沿用 `theme.value/change`。

浏览器同一 JavaScript 运行环境同时挂载一个 `App`。卸载后可挂载新的根模型。库在模块内保存当前界面状态和操作，卸载时释放。不同浏览器标签页各自持有自己的状态。

从旧版升级所需的模型及回调调整见[迁移清单](static-migration.md)。

## 领域、对象与集合

`ObjectNode` 用 `family` 区分 `standard` 和 `voucher`，单据额外提供只读 `type` 和封闭单据操作。`ListCollection` 承载独立查询、权限和保存边界。公开类型 `Collection` 包含 `ListCollection` 和首页 `Workbench`。栏目、分类与领域组织业务入口。

- `BusinessModel.work.members` 的类型为 `(Category | DomainGroup | ListCollection)[]`。工作区栏目和领域按数组顺序呈现。
- `Category.members` 是有序的领域与折叠分类数组。`DomainSection.members` 是有序领域数组。键在同层唯一，分类固定一层。
- `DomainGroup.members` 的类型为 `ListCollection[]`。Tab 和默认可读集合按数组顺序确定。各层成员使用自身的唯一 `key`。每个集合只定义一次，路由、工作台、关联和权限使用原集合引用。

```text
BusinessModel.work.members
├─ 基础资料（Category）
│  └─ 客户（DomainGroup）
│     ├─ 客户（ListCollection）
│     ├─ 账款设置（ListCollection）
│     ├─ 联系人（ListCollection）
│     └─ …
└─ 单据（Category）
   └─ 采购（DomainSection）
      ├─ AA 采购订单（DomainGroup，持有 AA 集合）
      └─ AB 采购收货（DomainGroup，持有 AB 集合）
```

侧栏显示栏目的折叠结构及领域链接。领域标签与可选有限语义图标由 `DomainGroup` 提供，链接以该领域第一个可读集合为目标。不可读的领域、空栏目和空分类自动隐藏。消费者可用 `hiddenFromNavigation` 表达单据类型停用等业务事实，已授权的集合链接仍可直达。根直属集合可通过路由、工作台或关联进入。

领域内容区按模型顺序用 Material Tabs 呈现多个获权集合，单集合直接展示。直达链接选中对应 Tab，切换 Tab 保持侧栏领域高亮。切换保留集合输入、条件和分页，已访问集合在 Tab 间往返时不重复查询，只挂载当前集合。各集合独立持有条件、结果、选择、分页、草稿及操作。字段分组及 RecordsNode 所属明细保留各自语义。

2026-11-18 接口修订规定，字段、分组、记录及其他有先后顺序的内容用数组表达。对象 `members` 数组决定字段和分组的顺序，同一对象内 `key` 唯一。`label` 是必填的显示名称，类型为字符串。`ListCollection` 按 `columns` 数组的顺序、`key` 和 `label` 呈现，空表也有表头。已获权字段可以被独立集合的显式列或打印路径引用。缺少显式列所指的成员时应给出可定位的模型错误。

### 所属明细与工作台行

0.48.0 移除 `RecordsNode.columns`。消费者在源码中一次声明有序的行成员，创建每条记录时据此构造独立的 `ObjectNode.members`。同一明细的各行使用相同的成员结构、顺序和标题。

明细先裁剪无权行。桌面表格和手机卡片使用同一组字段，只显示在每条可读行上均可读的成员。字段按 `members` 的顺序呈现，按 `key` 对应，标题使用成员的 `label`。可见字段保留空字符串、空值和零的位置。字段因某一行无读取权限而被裁剪时，两端都隐藏该字段，不报模型错误。库检查可读行的成员键是否重复，并对比各可读行的成员结构、顺序和标签。发现不一致时反馈行位置。消费者负责保证每行都符合源码中的静态定义。

没有可读行时显示空态。首条可读行出现后，用既有成员呈现表格和卡片。工作台也按各行 `members` 的顺序呈现可读的摘要字段。独立集合列和打印模板列继续按各自的有序数组工作。0.47.0 使用原有的 `RecordsNode.columns` 和对象式根成员及领域成员。

明细增删只改变本地模型，随父对象保存。新增回调按同一份静态定义构造独立行及字段。嵌套对象只有分组含义时，保存由父对象负责。

## 集合路由与记录窗口

库管理浏览器历史和页面路由。`/app/` 定位到工作台集合，普通集合路径由静态集合键及层级推导。唯一键使用 `/app/<集合键>`，重名使用完整静态层级，每个路径段分别编码。部署服务器将 `/app` 和 `/app/*` 交给前端应用入口。已知但不可读的集合不会读取数据。当前实现没有可读工作台时，首页进入首个可见领域的首个可读集合；没有可见集合时显示空工作区。未知页面显示 404。认证及强制改密优先呈现，登录后恢复原页面地址。

记录查看、编辑和新增属于工作区窗口。消费者在可打开窗口的 `ObjectNode` 上提供静态 `businessType`，记录的 `identity` 表示同一类型中的具体对象。每种类型只有一个窗口。工作台、关联或列表入口可直接打开窗口，当前页面地址和集合分页保持原样。窗口直接编辑原响应式对象，消费者可用 Vue 监听字段和明细变化。保存调用 `operations.update.run(record)`，所属明细的 `create/remove.run` 接收原 `RecordsNode`，本地明细随父对象提交。保存成功后消费者写回确认值，窗口更新本次保存范围的快照。切换同类记录时对比当前业务值与快照。有差异时先确认，取消则留在原记录，继续切换时离开的对象保留当前值。会话结束时释放窗口。

### 从地址打开页面或记录

宿主通过组件引用调用 `App.openUrl(url: string): boolean`。例如 `openUrl("/app/customers")` 切页，`openUrl("/app/AB?id=560009")` 打开单据窗口并保留地址栏、浏览器历史及列表上下文。单据、资料和其他对象共享集合路径和字符串身份规则。仅接受同源地址；空或重复 id、未知参数、片段或不可读目标返回 false。

UI 先从集合当前选中对象和已加载结果按身份取记录，均无结果时调用可选 `ListCollection.resolveRecord(id)`。回调从源码静态定义取得或构造原业务对象，记录声明相同的 `identity`，并通过 `businessType` 加入工作区窗口。UI 核对记录归属和读取资格，窗口仍调用对象的 `load(id)` 并执行未保存变更确认。返回 true 表示受理，后续读取、重试及确认由窗口完成。

### 按需读取

工作台和分页列表均属于集合层。工作台作为可选的首页集合保留有序呈现的四个固定区块。三个读取回调均可省略：

| 目标 | 回调 | 数据范围 |
| --- | --- | --- |
| 分页集合 | `load({ page, pageSize })` | 读取指定页，查询条件来自所属集合 |
| 记录 | `load(id)` | 读取该记录的字段和所属明细 |
| 工作台集合 | `load()` | 读取四块中当前获权的内容 |

集合、工作台及窗口外的对象按会话复用首次读取结果。正式记录每次打开窗口或切入同类型窗口时执行已声明的 `load(id)`，回调完成前将业务值写回原对象。读取中暂停编辑，失败时可以重试，成功后窗口复制业务值作为未保存比较快照。无 `load` 的记录及身份为空的新增记录用打开时的业务值建立快照。重复打开当前记录和切换到已打开的其他类型窗口只激活窗口。分页调用集合 `load`。显式「查询」从第一页开始，调用已配置且启用的 `operations.query.run`，未配置查询操作时调用 `load`。分页成功后消费者一起更新 `page`、`items`、`total`，失败时保留已有结果。消费者校验迟到结果的会话、目标和请求有效性，再更新数据或消息。

## 操作与会话

节点读取资格及会话修订自 0.49.0 起适用。固定使用 0.48.0 的消费者可查阅[该版本的接口](https://github.com/hansonyu183/zerp-ui/blob/ui-v0.48.0/docs/interfaces/README.md)。

消费者把业务状态和权限直接反映到同一个响应式模型。集合和业务节点提供可选的 `readable: boolean`，在会话允许访问时省略表示可读。`readable: false` 隐藏节点及其所属内容，并阻止经由列表列、链接和打印读取该内容。表单沿用 `readOnly`，操作沿用 `disabled`。实际请求的鉴权和状态校验由后端负责。

UI 只显示可读节点上已配置且 `disabled` 为 false 的业务操作按钮。入口隐藏时不得调用 `run`。UI 调用前读取当前模型状态并防止同一目标重复执行。`Operation.run(input)` 同步返回 `void` 时直接结束，返回 `Promise<void>` 时由 UI 自动管理忙碌状态直到 Promise 完成。发起请求的回调返回代表请求完成的 Promise。需要解释业务阻塞或核实结果时，由模型 `messages` 提供信息。实现及验证状态见 [UI 规范验证覆盖](../ui-preferences-coverage.md)。

`messages` 中设置 `blocking: true` 的消息逐条以模态弹窗呈现。用户点击「确定」后结束这次提示；等待确认时应用背后的界面不可操作。确认只处理消息呈现，实际业务操作及资格仍由消费方模型决定。同一目标、级别和文案同时待确认时合并为一次。普通消息在界面顶部逐条替换，到时自动退出呈现。当前操作的阻塞原因或待核实提示保留就近入口，最多显示最近一条。提示消失后不会因界面重新挂载而重播同一条消息；消费方仍持有和管理 `messages` 数组。

登录前一次定义完整集合及认证结构并传入同一个响应式根对象。UI 管理当前目标的读取、等待和重试呈现。消费者实现读取、业务校验及结果回写。`Session` 只声明会话状态和 `owner`。匿名状态的 `owner` 为 `null`，就绪和强制改密状态的 `Owner` 由账套 `ledger`、操作员 `operator` 和会话代际 `generation` 组成。同一账号重新登录也应更新代际，使上一会话的迟到结果失效。

登录时由消费者更新业务数据、节点和操作状态，再写入 `model.session`。匿名时隐藏受保护内容并显示可用的登录操作。

登出由消费者注销后端会话、清空身份/权限、输入、记录、条件、分页、选择、消息和作用域缓存，并使迟到回写失效；UI 清理自己的 busy/反馈并返回认证。直接裁剪对象时，本次宿主保留完整静态结构，仅裁剪呈现；消费者清除旧会话业务数据。再次登录或增权须恢复新获权内容，根对象引用不变；清理不删除后端业务记录或历史审计/恢复证据。

工作台至少有一块可读区块且存在 load 时提供「刷新」。四块随权限分别裁剪。桌面重要信息在上方横跨，下方单据、报表和资料三等宽列，手机依次纵排。

## 引用与格式

普通引用是搜索下拉，树形引用是可展开的搜索下拉，均只负责单选或多选。静态候选直接写入 `options`。动态候选在打开下拉时由 UI 按需调用 `load`，消费者在回写 `options` 前校验 owner 和业务依赖。UI 按会话、字段与 `scopeKey` 复用目录读取；`scopeKey` 变化后失效，下一次打开按需重读。前端搜索和分页使用当前候选，树搜索保留祖先路径。`selectable: false` 的候选可回显但不能新选。历史选值的 `label` 由消费者提供，候选缺失时保留选值，作用域契约见 [#165](https://github.com/hansonyu183/zerp-ui/issues/165)。

格式选项只作用于只读展示、列表和打印，编辑与 API 保留原值。date 是无时区 YYYY-MM-DD；datetime 是有时区 ISO 8601；未填用空字符串。省略 format 时使用本地语言，日期显示年月日，日期时间增加时分秒；显式提供的年月日/时分秒选项决定显示分量。timeZone 缺省采用本机时区，hour12 缺省遵循语言。decimal 缺省保留原精度、不分组、不附加单位；显式 maximumFractionDigits 可对展示按十进制四舍五入，不能经 Number 损失精度；显式最大小数位关系不合法时反馈格式错误，不修改 value。

## 打印 JSON

`itemPrintTemple` 为满足资格的记录行及只读详情提供单条打印入口，只使用当前读取到且 `printable` 为 true 的正式记录，排除 `draft`。`printTemple` 为满足资格的当前页提供集合打印入口，只使用 `items`。缺少模板、没有可打印记录或资格不满足时，入口隐藏。符合资格且相关操作正在处理时，入口禁用。模板采用可序列化的有限 JSON。

`ObjectNode.printable` 是消费者对正式对象及所属明细当前值的权威确认。新增、未确认的模型值、提交中和未知结果应为 `false`，经有效读取、保存或核实后的权威值才可置为 `true`。窗口编辑直接更新模型值，消费者监听变更并更新 `printable`。打印读取正式记录及当前页既有结果。当前页中任一获权记录不可打印时，整页入口不可用。预览及系统打印调用前再次重检，具体业务原因由消费者通过 `messages` 提供。

纸张、页边距、区域坐标和尺寸单位为毫米，字号为 pt。页眉/页脚每页重复，正文在其剩余高度内按 band 顺序布局。record band 相对当前单条记录绑定字段；records band 的空路径只在集合模板中表示 items，非空路径在单条模板中逐级查找对象 members 的 key，最终指向 RecordsNode。列路径相对每行记录。页眉/页脚字段只在单条模板中绑定当前记录；集合模板的页眉/页脚使用固定内容。

字段按节点格式输出，引用输出 `label`，布尔值输出“是/否”，空值输出空文本。对象、明细、附件、密码或 `secret` 不能作为普通 `field` 打印。没有读取权限的内容不得进入打印结果。行高、固定区块、页码和分页规则见[模板布局与分页](../printing/contract.md#measured-json-voucher-templates-179)。

字段路径、尺寸、颜色、字体或位图无效时阻止打印并反馈，不跳过错误或显示原始对象。图片仅允许内嵌 PNG/JPEG/WebP/GIF；颜色和字体沿现有有限打印能力，颜色为六位十六进制。UI 负责绑定、分页、预览及用户明确点击后的原生打印调用；打开/关闭对话框不证明实体打印成功，也不自动更改业务打印次数。库解释模板并生成有限文档。关闭预览、修改数据或切换会话会使旧排版失效。正式发行及真实产品接入分别验收。

## 有限业务能力

对象只区分 standard/voucher。既有资料审批、流程、处理、批次、报表及输出通过固定的 document/workflow/processing/batch/report/output 能力表达，各自 operations 的键由类型封闭。它们不改变对象成员结构，不构成另一个宿主或任意命令配置。

`OutputNode` 接收已经生成的有限文档，并提供显式实体结果确认，详见[打印契约](../printing/contract.md)。`InteractionNode` 提供有限问题、目录和网格。`ListCollection.report` 接收消费者提供的合计、呈现结构及带目标的单元格。关联和报表下钻的权限边界见[工作台与记录目标链接](#工作台与记录目标链接)，各业务族的能力对应见[迁移清单](static-migration.md)。

## 验收边界

通过唯一公开 App/model 入口、同一候选 tgz 的物理独立安装、合成模型及模拟回调验证。仅对新精确格式与模板算法补必要的纯函数检查；不导出私有 VM。UI 条款逐项核对，实际命令与退出码、确切源码 SHA、tgz 摘要及缺口回写 GitHub #159 及实施票。

合成消费者仅用于库的公开行为验收，使用合成数据和浏览器打印。正式发行原包见[固定版本安装](../../README.md#固定版本安装)。真实产品接入、API/E2E 及部署结果以消费者对应工单的验收记录为准。

## 脚本菜单与树动作

`menu` 和 `tree` 项可以关联真实独立集合，或提供 `InteractionAction`。自 0.49.0 的节点资格修订起，动作要求所属 `InteractionNode` 在当前会话可读可写，并且条目与操作均未禁用。UI 防止重复执行，条目或操作替换、节点移除及会话或模型切换后隔离迟到失败反馈。业务回调在实际回写前验证有效性。`related` 使用 `CollectionTarget`，`download` 使用集合导出或独立文件下载。能力来源见 [#164](https://github.com/hansonyu183/zerp-ui/issues/164)。

## 独立脚本文件下载

`download` 的目标可为执行集合导出的 `CollectionTarget`，或调用独立文件回调的 `InteractionDownload`。独立文件下载要求所属节点可读、条目与操作可用，因此也可出现在只读详情中。UI 在调用前重检资格并防止执行中重复调用。文件内容和下载端口由消费者负责。下载目标用于 `download`，`menu` 和 `tree` 的写入动作使用 `InteractionAction`。能力来源见 [#167](https://github.com/hansonyu183/zerp-ui/issues/167)。

## 工作台与记录目标链接

集合目标保留真实页面链接和原生修饰键行为。带记录的目标只打开该记录的窗口，工作台和其他页面保持原路由。此规则修订了 #173 的详情 URL 约定。

Workbench.targets 是从快捷行到 CollectionTarget 的可选 ReadonlyMap，manageReports 提供“管理常用报表”入口。目标只保存已有业务节点引用；外页记录经当前公开有限目标关系归属到其独立集合，定义目标时不预取，也不把记录加入当前页。实际打开记录窗口时更新目标集合的 `selected`。实际成员归属优先，已属于另一个根的记录目标拒绝；权限仍沿当前 owner/集合/记录授权。移除目标边、撤权或切换身份后旧链接失效。无可打开目标的可读行只呈现摘要。

按钮、密度、主题和领域 Tab 的呈现要求见 [UI 规范](../ui-preferences.md)。
