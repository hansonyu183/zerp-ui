# 纯 API 结构驱动 UI · 目标协议 v1

状态：**design-only，尚未实现**。权威规格与后续决策：[GitHub #106](https://github.com/hansonyu183/zerp-ui/issues/106)。本文是该规格的版本化技术工件，不维护第二套任务状态。

本次只设计规范及完整 OIT 目标 API，不修改运行代码、现有接口、依赖、数据库、部署或发行包。当前 0.25.0 的页面定义／Adapter 接口仍然运行，本文不声称已迁移。

## 目标与边界

后端提供符合统一结构的 API；UI 运行时发现能力，决定导航、页面、View、列表／树／表格／Form、编辑控件及响应式布局。新增符合既有协议的业务资源不需要重新发布前端；新增协议能力必须升级库。

后端拥有业务规则、身份、授权、数据范围、精度、事务、脚本执行与权威证据。API 不下发菜单树、前端路由、组件名、page/view/layout、CSS、hidden/disabled、任意前端函数或模板。名称、资源关系、操作资格和数据 Schema 是所有 API 消费者都需要的业务事实。

这项**目标决定**取代 #40/#47 中消费者逐页装配的目标边界，纠正 #104 关于后端下发导航分组的方向；历史记录和发行工件保持原状。

目标公开 Vue 组件仍为 AuthPage/AppPage。统一 createApiApplication 入口只接受 API base、安全传输、会话／账套作用域、路由历史、耐久存储、品牌及主题。旧 define*Page、逐页 Adapter 和领域区块装配转为库内部实现；不新增页面特例注册口。本阶段不修改任何导出。

## 工件

- [最小 Schema](schema.md)：关键词、格式、有限数据类型、静态／动态 Schema 绑定。
- [API 协议](protocol.md)：发现、资源、关系、草稿、操作、查询、文件和作业。
- [UI 推导及权限](inference.md)：确定性结构规则、控件规则、授权与生命周期。
- [机器可读 profile](profile.json)：v1 allowlist，不是业务 Schema 或 UI 配置。
- OIT 目标 API、66 类基础资料字段、全部现状路由映射及场景：`oit-go/docs/api-design/README.md`；跨仓库工件以该文记载的 SHA／摘要为准，不从本仓库链接推断已部署。

## 设计验收

只做文档及协议静态验证：OpenAPI/Schema 引用、最小子集、全部当前路由覆盖、内置资源字段、动态绑定和场景样例。合成样例不是真实后端验收。既有库全量运行测试、tgz 发行、浏览器及数据库均不属于本次规格任务。

新增关键词必须提供当前具体场景及旧子集不能表达的证据，不因 JSON Schema 标准中存在该能力而纳入。

关联字段、一对一扩展和主从子明细的完整推导见 [关系整合](relationships.md)。
