# Structured print output (#58 / #59)

`PrintDocument` describes physical sheets. Supply a prepared document as `OutputNode.value` in `App`. Consumers can use `NonNullable<OutputNode["value"]>` as its type, importing `OutputNode` from `@zerp/ui/model`. Use a nonempty document ID, 1–10,000 pages, unique nonempty page keys, and unique nonempty item keys within each page. Sheet width and height each range from 1 to 2,000 mm. Specify colors as `#RRGGBB`. Every supplied page produces one output page. Business pagination, expressions, subtotals, bitmap and barcode generation, and print authorization remain consumer responsibilities.

Coordinates, sizes and `lineWidth` are millimetres. Document `rotation` is clockwise 0, 90, 180 or 270 degrees around the sheet centre, translated to the output page so all original sheet corners remain inside the rotated dimensions. Item coordinates always refer to the original width/height. Output width/height swap for 90/270. Negative/outside geometry is rejected before rendering; content and rotated watermarks are clipped at the sheet boundary. Watermarks are a library-owned overlay above all items, rotate around their own centre and accept opacity 0..1. They cannot supply markup/styles.

Text defaults to 10pt, unitless `lineHeight: 1.2`, `wrap: "word"`, left alignment, normal weight. Explicit newlines remain; long words and Chinese can break within the box. `wrap: "none"` preserves lines without automatic wrapping. Text is clipped to its fixed box, with no ellipsis or auto-size. Line height is limited to 1..3, size to 1..200pt. Strokes/borders default to 0.2mm and allow 0.05..10mm; strokes occupy the box's inside edge. A line is the horizontal top stroke, and may have zero height. Consumers must leave enough space for glyphs and strokes. Library-generated finite SVG primitives preserve fractional physical stroke widths in browser/PDF output, including text/image borders. These primitives accept only validated geometry/color facts; consumer SVG input remains rejected. Boxes smaller than their stroke or lines extending beyond the sheet are rejected.

Fonts are the finite `sans-serif`, `serif`, `monospace`, and `cjk-sans` choices. Generic families intentionally use the browser's configured platform fonts and do not promise machine-independent metrics. For Chinese output choose `cjk-sans`: it resolves the first installed exact local face from Noto Sans CJK SC (NotoSansCJKsc-Regular), PingFang SC (PingFangSC-Regular), Microsoft YaHei (MicrosoftYaHei). Local loading uses these exact PostScript/full face names, not a generic family guess. Install one before use (Linux CI: `fonts-noto-cjk`). The preview waits for that face and image decoding; an unavailable face or invalid bitmap keeps opening disabled with an error. It never silently substitutes another CJK font. This is a controlled local-font contract, not an embedded font redistribution or physical-printer certification. Different listed fonts still require consumer layout verification.

Images remain embedded PNG/JPEG/WebP/GIF only, contained within the supplied box. SVG, remote URLs, scripts, arbitrary families, invalid geometry/opacity/strokes/rotation are rejected. Browser image decoding rejects malformed data. Consumers supply bitmap and barcode data, including any required quiet zone.

For `OutputNode`, the user opens native printing by explicitly clicking the available print action after fonts and images are ready. A disabled action or busy node prevents opening. After the browser `print()` call returns normally, the UI invokes the configured `operations.print.run` if the operation is still eligible. Physical outcomes require a separate eligible `confirmPrinted` or `confirmNotPrinted` action. The collection JSON template preview has no physical-result registration action.

## Migration and evidence

Existing documents continue using default unrotated dimensions, existing finite generic families and clipped text. For physical stroke parity, set `lineWidth` explicitly rather than relying on the previous 1px default. Set line height and wrapping explicitly where old layouts depended on browser defaults. Convert legacy watermarks/rotation to these structured facts; never copy old CSS or arbitrary font-family strings. No OIT/production parser or fallback runtime is provided.

The historical synthetic print fixture's tgz smoke checked rendered millimetres, two PDF pages with the rotated MediaBox, actual bitmap QR decoding, Chinese text and wrap/clipping geometry, font availability and native-dialog authorization. Browser PDF/bitmap output is evidence of browser rendering only; no physical printer, production data or real ZERP API was tested.

## Rotated PDF regression (#65, 0.11.2)

The library uses explicit millimetre translation/rotation from the top-left origin and strict containment on fixed page/sheet boxes. This preserves the same logical coordinate contract while preventing Chromium print fragmentation from moving multiline baselines or clipping rotated footers. Screen preview alone does not establish PDF geometry. The [0.11.2 fixture](https://github.com/hansonyu183/zerp-ui/blob/ui-v0.11.2/docs/printing/contract.md) accepted `?rotation=0|90|180|270` on `/printing` and exercised three synthetic pages in both the installed tgz and built example. PDF.js inspects actual PDF baselines in logical millimetres and renders each PDF page to verify footer ink and decode the QR bitmap. The checks include page count, physical MediaBox, line spacing and per-page footers. PDF tooling is development-only. The current `check:print` runs the measured JSON template scenario described below. The rotation and QR results above are historical evidence.

## Measured JSON voucher templates (#179)

Through `ListCollection.itemPrintTemple` / `printTemple`, the library binds held model values, measures table text in an isolated browser document using the same finite output styles, and paginates the result. `rowHeight` and `headerHeight` are minimum heights in millimetres. Table columns also accept the existing finite text style properties. Measurement includes actual glyph extents and a finite text `insetTop` in the generated document where ascenders exceed the line box; templates do not configure that inset. Wrapped text grows a whole row; page breaks repeat the measured header and never split a row. A row plus its heading that exceeds the entire usable page fails with the band, row and record key. Fixed `record` bands and ordinary text boxes retain their explicit sizes.

A `PrintElement` with `kind: "pageNumber"` uses the ordinary text geometry/style and renders `第 X / Y 页` after pagination. Put a final `record` band after the detail table for totals and signatures: it appears once and moves intact to a new page when needed. Totals bind existing model values; the library does not calculate business totals. The A4 synthetic example is available as “打印示例” in the model consumer.

Measurement waits for the controlled CJK face where used and for font readiness. Closing the preview, changing the template/data or changing UI scope cancels the old measurement and removes its iframe. Font/image readiness and current authorization still gate the explicit native print action. `pnpm check:print` independently installs the tgz and checks its public consumer plus the built example, and checks PDF output rendered by Chromium from the preview content. The test replaces the native `window.print()` call with a stub. PDF output is stored in `.scratch/print-output/` and scenario evidence in the package-check directory. Native dialogs, physical printers and real business APIs require separate verification.
