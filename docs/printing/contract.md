# Structured print output (#58 / #59)

The public `PrintDocument` is a physical sheet description consumed only through `AppPage`'s task printing facts. It is not HTML or CSS. Business pagination, expressions, subtotals, bitmap/barcode generation and print authorization remain consumer responsibilities. Every supplied page produces one output page.

Coordinates, sizes and `lineWidth` are millimetres. Document `rotation` is clockwise 0, 90, 180 or 270 degrees around the sheet centre. Item coordinates always refer to the original width/height. Output width/height swap for 90/270. Negative/outside geometry is rejected before rendering; content and rotated watermarks are clipped at the sheet boundary. Watermarks are a library-owned overlay above all items, rotate around their own centre and accept opacity 0..1. They cannot supply markup/styles.

Text defaults to 10pt, unitless `lineHeight: 1.2`, `wrap: "word"`, left alignment, normal weight. Explicit newlines remain; long words and Chinese can break within the box. `wrap: "none"` preserves lines without automatic wrapping. Text is clipped to its fixed box, with no ellipsis or auto-size. Line height is limited to 1..3, size to 1..200pt. Strokes/borders default to 0.2mm and allow 0.05..10mm; strokes occupy the box's inside edge. A line is the horizontal top stroke, and may have zero height. Consumers must leave enough space for glyphs and strokes. Browser borders can quantize to device/CSS pixels (the verified Chromium screen preview maps a declared 0.5mm border to 1 CSS pixel). Millimetre facts do not imply subpixel physical-printer calibration; verify output on the target printer where precise stroke calibration matters.

Fonts are the finite `sans-serif`, `serif`, `monospace`, and `cjk-sans` choices. Generic families intentionally use the browser's configured platform fonts and do not promise machine-independent metrics. For Chinese output choose `cjk-sans`: it resolves the first installed exact local face from Noto Sans CJK SC (NotoSansCJKsc-Regular), PingFang SC (PingFangSC-Regular), Microsoft YaHei (MicrosoftYaHei). Local loading uses these exact PostScript/full face names, not a generic family guess. Install one before use (Linux CI: `fonts-noto-cjk`). The preview waits for that face and image decoding; an unavailable face or invalid bitmap keeps opening disabled with an error. It never silently substitutes another CJK font. This is a controlled local-font contract, not an embedded font redistribution or physical-printer certification. Different listed fonts still require consumer layout verification.

Images remain embedded PNG/JPEG/WebP/GIF only, contained within the supplied box. SVG, remote URLs, scripts, arbitrary families, invalid geometry/opacity/strokes/rotation are rejected. Browser image decoding rejects malformed data. Generate high-resolution bitmaps with sufficient quiet zones; the synthetic QR sample is decoded from the browser-rendered output, including its rotated sheet. The library does not generate business barcodes.

Only explicit clicking while the consumer grants `state: "opened"` opens the native dialog. Loading, recovery, and reload do not print. Closing/cancelling the native dialog does not report physical success; printed/not-printed remain explicit operation facts. Font/image readiness does not grant authorization. Revoking authorization immediately disables the opening action.

## Migration and evidence

Existing documents continue using default unrotated dimensions, existing finite generic families and clipped text. For physical stroke parity, set `lineWidth` explicitly rather than relying on the previous 1px default. Set line height and wrapping explicitly where old layouts depended on browser defaults. Convert legacy watermarks/rotation to these structured facts; never copy old CSS or arbitrary font-family strings. No OIT/production parser or fallback runtime is provided.

The capabilities consumer's print fixture is synthetic. Its tgz smoke checks rendered millimetres, two PDF pages with the rotated MediaBox, actual bitmap QR decoding, Chinese text and wrap/clipping geometry, font availability and native-dialog authorization. Browser PDF/bitmap output is evidence of browser rendering only; no physical printer, production data or real ZERP API was tested.
