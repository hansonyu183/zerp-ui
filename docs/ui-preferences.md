# 个性化 UI 规范

本文集中维护项目所有者已确认、当前有效的 UI 约束，适用于本库的设计、实现、重构、模型迁移、审查与验收。2026-11-15 根据历史会话及关联工单整理，2026-11-16 按用户明确要求补充常规 UI 判断与交付清单原则。它规定目标行为，不证明当前实现符合要求；正式业务规格、决策与实施状态仍维护在 GitHub Issues。

编号于 2026-11-15 按用户要求加入；编号永久保留，删除不复用，新增不重排。复合条款中的断言以编号加后缀引用；覆盖清单及细节判断说明见 [验证覆盖](ui-preferences-coverage.md)。编号和验证清单不改变原要求，尚未确认的量化提议不作为验收阈值。

## 执行与维护

1. **UI-GOV-01** 开始 UI 相关工作前，读取本文及当前工单、父规格，列出本次受影响的条款。模型或宿主迁移须覆盖所有被替换呈现路径的条款。
2. **UI-GOV-02** 沿用已确认的风格、布局和交互。模型、接口或内部实现的迁移不授权重新设计 UI；功能可用、类型检查通过或旧组件仍存在，均不能代替新公开入口符合规范的证据。
3. **UI-GOV-03** 用户明确新增、修订或撤销要求后，在同一任务内直接更新本文对应条款，记录确认日期及来源，移除已失效表述。自动维护以用户确认或可核对的已确认规格为依据；Agent 建议、当前实现和测试结果本身不构成新规范。
4. **UI-GOV-04** 最新明确的用户决定优先；历史要求只在其适用范围内延续。已能判定的修订直接归并；确实影响实现且无法判定的冲突，按 UI-GOV-06 纳入开发交付时的一份未决清单。正式规格需同步时按议题流程处理，历史验收记录保持原义。
5. **UI-GOV-05** 交付前逐项核对受影响条款，记录符合证据及未完成项。仅运行必要的定向检查；布局和交互用公开入口的行为或几何检查验证，不以无关全量测试替代。发现偏离时，在已授权范围内修复；否则明确报告，不能修改规范来迁就实现。

6. **UI-GOV-06** 文案和常规 UI 细节由 Agent 按现有已确认要求、业务语境及项目既有能力直接判断并完成开发与审查，不逐项要求用户确认，不把常规实现取舍升级为新的全局偏好或强制量化标准。只有业务含义不明确或需要改变已确认要求时，才保留未决项；完成其余明确且已授权的开发后，随交付提供一份合并清单，列明问题、影响、建议及尚未实施或待定的部分，开发过程中不反复提问。不擅自补造业务含义或改变已确认要求，不把待定部分宣称已完成；没有此类未决项时无需确认清单。

来源：2026-11-16 用户本轮明确要求：“文案和常规 UI 细节由你按现有要求判断，只有业务含义不明确或需要改变已确认要求时，在完成开发后留1份清单”；此决定修订此前将常规文案、留白等逐项列为用户确认事项的处理方式。

## 一致性、主题与密度

- **UI-THEME-01** 页面和领域区块内部布局由库统一负责，消费者提供业务模型及事实；共性行为在库内实现，不要求逐页面补样式或另写布局模板。
- **UI-THEME-02** 优先复用已验证的 Vuetify 能力。认证、业务、工作台、弹层、反馈及输入控件完整采用一致的 Material 语言，并实际响应 MD1/MD2/MD3 Blueprint 与明暗切换。
- **UI-THEME-03** 默认 MD3 浅色。主题预设菜单位于独立明暗切换左侧；切主题保留明暗，切明暗保留主题。本机偏好持久化归消费者。
- **UI-THEME-04** 通过主题、组件默认属性和库内公共样式统一呈现，清除无必要的页面级微调。主要提交、普通操作、危险确认具有可辨认的层级。
- **UI-THEME-05** 全 UI 采用紧凑密度：正文、按钮、字段标签、菜单、导航、卡片和反馈为 12px；标题保留 18/16/14px 层级。手机原生输入保持 16px，避免聚焦缩放。
- **UI-THEME-06** 桌面动作最小 32px，输入采用 compact 密度，App Bar 为 48px；手机保留 48px 触控区域。字段之间间距合理，表单和卡片减少冗余留白。

来源：2026-09 主题与公共样式要求、2026-11 全 UI 紧凑要求；[#49](https://github.com/hansonyu183/zerp-ui/issues/49)、[#85](https://github.com/hansonyu183/zerp-ui/issues/85)。

## 顶栏与反馈

- **UI-SHELL-01** App Bar 固定视口顶部，内容按实际高度避让；滚动、响应式变化和弹层出现时互不遮挡。菜单、弹窗、抽屉遮罩、子项编辑及消息位于顶栏下方。
- **UI-SHELL-02** 顶栏固定沿用 ZERP 的组合与顺序：导航开关、可回首页的品牌区、间隔、主题预设、明暗切换、头像与账户菜单。品牌区包含品牌头像、产品名和企业名。
- **UI-SHELL-03** 账户名称与入口随会话可用，不等待全站业务读取；个人资料、改密、退出可达。窄屏收起企业名及账户文字，保留入口和可访问名称。
- **UI-SHELL-04** 页面主标题位于顶栏下方；上下文已明确的业务名称不在组件头重复堆叠。
- **UI-SHELL-05** 成功、失败、警告、状态及字段校验出现、更新或关闭时，不挤动内容、不增加文档流占位、不改变表格行高。字段错误使用清楚可读的浮层等稳定呈现方式，长消息在限定区域内滚动。
- **UI-SHELL-06** 业务阻塞原因及核实入口持续可达；关闭消息只改变呈现，不改变业务结果。

来源：2026-07 至 11 月固定顶栏、稳定反馈和账户要求；[ADR-0001](adr/0001-library-owned-page-layout.md)、[#40](https://github.com/hansonyu183/zerp-ui/issues/40)、[#76](https://github.com/hansonyu183/zerp-ui/issues/76)、[#148](https://github.com/hansonyu183/zerp-ui/issues/148)。

## 列表与操作

### 桌面

- **UI-DESKTOP-01** 保持紧凑表格，保留完整字段，尽量避免横向滚动；超宽处理不擅自把桌面列表改成卡片。
- **UI-DESKTOP-02** 操作整合为第 2 列，保持容易找到；排序放在相关表头，不占筛选栏。
- **UI-DESKTOP-03** 表格内编辑控件采用简洁模式，校验不改变行高。

### 手机

- **UI-MOBILE-01** 列表及适用的明细表格切换为逐条记录卡片，保留字段、记录身份、选择、合计及获准操作，避免横向溢出。
- **UI-MOBILE-02** 字段采用内容驱动的流式布局：名称和值同行，多个短字段可同排，长值自然换行。
- **UI-MOBILE-03** 卡片首行左侧复选框、右侧操作，下方为字段；单侧缺省时另一侧位置稳定。全选当前页入口显示可见文字和已选数量，保持半选及禁用语义。

### 操作

- **UI-ACTION-01** 同一意图使用同一语义图标，反向动作可区分。普通行操作最多显示 3 个常用项，其余进入“…”菜单；手机根据宽度进一步收纳次要项。
- **UI-ACTION-02** 桌面行操作为图标，中文名称用于无障碍标签及 hover/focus hint；手机为图标加短文字，不依赖悬停。
- **UI-ACTION-03** 查看、编辑及业务操作按实际状态、权限和业务限制提供；不能出现允许编辑却无可达保存入口或原因说明的状态。查看与编辑入口避免重复。
- **UI-ACTION-04** 新增按钮、明细新增提示和新增弹窗标题统一为“新增”，成功提示为“新增成功”；通过所属区块区分多个入口。提交、克隆、删除、移除和上传等保持各自语义。

来源：2026-07/09/11 手机卡片、2026-10 操作列及 2026-11 桌面紧凑要求；[#29](https://github.com/hansonyu183/zerp-ui/issues/29)、[#71](https://github.com/hansonyu183/zerp-ui/issues/71)、[#74](https://github.com/hansonyu183/zerp-ui/issues/74)、[#78](https://github.com/hansonyu183/zerp-ui/issues/78)、[#83](https://github.com/hansonyu183/zerp-ui/issues/83)。

## 表单、详情与 Tab

- **UI-FORM-01** 查看、新增、编辑共用内容结构和字段顺序；详情允许使用只读表单。支持复杂对象、集合、明细及嵌套内容，普通字段与集合行使用一致的直接编辑体验。
- **UI-FORM-02** 列表查看和编辑通过模态、抽屉等覆盖式交互呈现，保留列表筛选、分页和滚动位置，关闭回到触发入口；新增沿用统一编辑容器。避免在长列表底部展开详情，或通过替换列表丢失上下文。
- **UI-FORM-03** 表单按容器宽度自适应：筛选最多四列、编辑最多三列、短表单单列，长文本与子表独占行。合理留白，字段错误不另占大块空间。同一表单列的普通输入、密码与引用控件保持一致的左右边界和密度；错误入口不挤窄控件。
- **UI-FORM-04** 多字段查看与编辑、相似领域区块统一分组。多组显示真正的 Material Tab，单组直接展示，零组无空容器；保留明确选中态、窄屏滚动和键盘交互，Tab 与浮动标签不重叠。
- **UI-FORM-05** 分组及顺序来自模型结构，不要求消费者重复提供 Tab 配置或布局模板。2026-11-16 用户确认目标对象使用有序 members 数组，删除 form；label 为 null 的整个节点不在对象详情/编辑中显示，仍可通过 key 用于显式列引用和打印。保留模型顺序，不硬编码数量、业务名称或 history 特例。
- **UI-FORM-06** 对象的多个分组默认首个可见 Tab，切 Tab 保留模型输入及应保留的查询、分页上下文；不同独立业务对象保持各自写入边界。2026-11-17 用户修订：全局导航指向根直属或领域分组内的独立 Collection，领域分组本身不是独立导航或保存目标；多个获权集合在领域内容区使用真正的 Material Tabs，按模型顺序呈现，默认首个可见集合，单集合直接展示、零集合不留空容器。切 Tab 保留各集合输入、条件和分页，不重复查询已访问集合；选中详情及编辑留在所属集合内，RecordsNode 子明细随父对象保存。
- **UI-FORM-07** 所属内容使用可辨认的业务名称及正确层级，不能把多个不同目录统一标成“字典值”。2026-11-17 用户修订：客户领域可以包含客户、账款设置、联系人、分类、分组、属性定义及相关字典等并列独立集合；采用领域分组节点组织入口并恢复并列集合的 Material Tab 呈现，不拥有整体保存，各集合独立查询、授权和保存。字段分组及所属明细仍在 ObjectNode 内呈现，不将独立集合塞入 ObjectNode.members；见 #152。
- **UI-FORM-08** 输入直接更新模型值；当前写入、冲突和未知结果恢复边界见 [ADR-0004](adr/0004-reactive-business-model.md)。恢复上述交互不恢复已取消的普通草稿离开确认或前端冻结请求机制。

来源：2026-11-05 模态、11-06 至 08 分组、11-10“详情可以使用只读表单”及共用表单、11-14 聚合模型、11-15 Tab 和字典反馈；[#78](https://github.com/hansonyu183/zerp-ui/issues/78)、[#87](https://github.com/hansonyu183/zerp-ui/issues/87)、[#89](https://github.com/hansonyu183/zerp-ui/issues/89)、[#96](https://github.com/hansonyu183/zerp-ui/issues/96)、[#98](https://github.com/hansonyu183/zerp-ui/issues/98)、[#152](https://github.com/hansonyu183/zerp-ui/issues/152)、[#154](https://github.com/hansonyu183/zerp-ui/issues/154)。

## 导航与引用

- **UI-NAV-01** 有子项的导航分组默认收起，无子项的一级入口直接导航。侧栏省略“导航”标题，菜单开关保留无障碍名称但不显示“切换导航”提示浮层。
- **UI-NAV-02** 业务菜单使用语义图标；未知语义保留文本。手机选择后关闭抽屉，桌面侧栏可收起；正常链接保留修饰键及新标签行为。
- **UI-NAV-03** 显式导航投影决定分组、名称、顺序和目标，权限裁剪后隐藏无权入口及空组。2026-11-17 用户修订：目标导航可引用根直属或领域分组内的原 Collection，领域只组织入口；记录和子明细不成为全局入口；current 为 null 时显示已配置的工作台，否则进入首个获权集合，无获权集合则显示空工作区。
- **UI-NAV-04** 页面已有导航时，编辑组件不重复建立导航。移除无必要的动态导航和重复目录页，保留实际业务入口。
- **UI-NAV-05** 账套及普通引用使用搜索下拉，树形引用使用可展开的搜索下拉。候选按需完整读取并按作用域缓存，前端过滤、分页，输入防抖；过滤和翻页不逐次请求后端。单选点选即生效，多选在同一下拉内完成，保留历史值回显与禁用语义。2026-11-16 用户确认两种引用仅负责选值，不关联 Collection、不附带维护或跳转；来源为本轮引用接口决定，见 #152。
- **UI-NAV-06** 模型构造及导航遍历保持本地工作；用户权限在登录/会话恢复取得，UI 自动裁剪。当前页面读取不阻塞外壳、账户菜单和其他入口。

## 工作台与业务文案

- **UI-WORK-01** 工作台桌面为“1 横 3 竖”：重要信息横跨上方，下方单据、报表、资料三等宽列；手机重要信息在前，其余三块依次纵排。采用响应主题的 Material 卡片和列表，不以通用聚合 Tab 替代此已确认布局。
- **UI-WORK-02** 导航、标题、按钮和提示使用简短业务中文；上下文已明确分类时省略类别词，例如“客户资料”改为“客户”。同一功能名称一致。
- **UI-WORK-03** 只保留帮助操作、判断结果或理解风险的说明，移除无用说明卡片、请求编号及内部实现文案。错误说明业务影响和下一步，保留必要单位、校验及不可逆操作提示。
- **UI-WORK-04** 报表下钻返回保留输入条件、结果、页码及滚动位置；结果有效性仍由消费者业务事实决定。

来源：2026-08/10/11 文案要求及 2026-11-08 工作台布局；[#80](https://github.com/hansonyu183/zerp-ui/issues/80)、[#102](https://github.com/hansonyu183/zerp-ui/issues/102)。

## 打印

- **UI-PRINT-01** 纯前端单据打印采用有限 JSON 模板，由库绑定数据、排版、预览并在用户点击后打开系统打印窗口。明细文字默认自动换行，按真实字体测量撑高行并分页，跨页重复表头，同一行不拆页；整行连同表头超出可用纸张时明确报错。支持“第 X / Y 页”，末尾汇总及签字区仅输出一次并整体换页；汇总业务值由消费者提供。保留现有权限、printable 与静态模型边界，普通定尺寸文本框不自动撑高。

来源：2026-11-16 用户在“纯前端打印功能”会话确认业务单据与明细、开发者 JSON 模板、完善库内打印及自动行高，并授权执行完整方案；实施与验收见 [#179](https://github.com/hansonyu183/zerp-ui/issues/179)，本条取代 #152 中固定明细行高裁切的目标要求。

2026-11-16 用户进一步要求 oit-go“切换到纯前端打印”：网页通用打印使用源码 JSON 模板与已读取单据值，通过浏览器预览和输出，不再依赖通用打印服务、服务端任务或 Windows 宿主；后端继续提供单据读取权限及“审核后才能打印”等业务资格。已有独立原生打印及历史审计/恢复证据按所属业务边界保留，不作为网页打印 fallback。消费者切换及真实产品验收记录维护于 oit-go 的 `.scratch/frontend-browser-print/`，不以本库合成测试代替。

## 场景范围与修订边界

以下是已确认的消费者场景，不作为通用库中的硬编码业务规则：

- **UI-SCOPE-01** OIT 保留基础资料、单据等顶层分类，长菜单增加可折叠二级分类；单据按类型码排序、按首字母分组，如 AB/AC 同组。停用类型从导航隐藏，历史直达与配置维护仍按业务权限处理。单据配置独立放在系统管理，移除重复功能目录入口。
- **UI-SCOPE-02** KY/K1 共用 UI，通过完整静态模型和权限表达菜单、模块差异。2026-11-17 用户确认保留客户领域下多个并列集合的对象结构：领域分组可以包含客户、账款设置、联系人、分类、分组、属性定义及相关字典集合，名称及顺序按源码中的业务结构定义。领域内多个可见集合以 Material Tabs 切换，单集合直接展示；该组织关系不构成整体查询、授权或保存，各集合仍为独立业务边界；不恢复以可保存对象聚合独立集合的协议，见 #152。
