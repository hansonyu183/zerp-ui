# 个人 UI 要求

本文汇总项目所有者在 ZERP UI、ZERP 和 oit-go 中已经确立的 UI 要求，供页面设计、实现和审查使用。2026-11-04 经用户要求整合入本仓库；本文记录产品偏好，不维护第二套正式规格或实施状态。本次补充要求与修复验收见 [#71](https://github.com/hansonyu183/zerp-ui/issues/71)。正式规格与交付状态仍以 GitHub Issues 为准，布局决策见 [ADR-0001](adr/0001-library-owned-page-layout.md)，Material 实现与验证映射见[对照矩阵](material/README.md)。

## 顶栏、布局与反馈

- 顶栏固定在视口顶部，长页面滚动不带走顶栏。内容按实际顶栏高度避让，响应式变化后仍互不遮挡。
- 菜单、弹窗、抽屉遮罩、离页确认、子项编辑及消息全部位于顶栏下方。
- 顶栏顺序固定为：导航开关、可回首页的品牌区、间隔、主题预设菜单、独立明暗切换、头像与账户菜单。品牌区包含品牌头像、产品名和企业名。
- 账户菜单固定提供“名称与头像”“更改密码”“退出登录”。窄屏收起企业名及账户文字，保留入口与可访问名称。
- 页面唯一主标题位于顶栏下方的主内容区。
- 成功、失败、警告、状态及字段校验反馈出现、更新或关闭时，不挤动字段、列表和按钮，不改变文档流占位。长消息在预留区内滚动。
- 阻塞状态及核实、重读等恢复入口持续可达，不能只依赖自动消失的通知。关闭消息只改变呈现，不改变业务状态。
- 完整页面及领域区块内部的排布、间距、折叠和响应式布局由库统一负责。消费者提供字段、分组、顺序和业务事实，通过 AuthPage/AppPage 接入。

来源：[ADR-0001](adr/0001-library-owned-page-layout.md)、[正式规格 #40](https://github.com/hansonyu183/zerp-ui/issues/40)。

## Material 与主题

- 认证页和业务页完整采用一致的 Material 语言，覆盖字段、按钮、列表、报表、详情、菜单、弹窗、反馈和进度；优先复用现有 Vuetify 能力。
- 提供官方 MD1/MD2/MD3 Blueprint 对应的主题与组件默认属性，默认 MD3 浅色；保留各版本自身的呈现差异。
- 主题预设与明暗模式分别提供入口；主题菜单位于明暗切换左侧。切换主题保留明暗，切换明暗保留主题。
- 本机记住用户选择；偏好持久化归消费者。品牌颜色通过现有有限主题 API 提供。
- 字号、按钮和提示框配色统一由主题与 Vuetify 默认属性管理，主要提交、普通操作和危险确认具有清晰层级。

来源：[正式规格 #49](https://github.com/hansonyu183/zerp-ui/issues/49)、[ZERP 公共列表与导航](https://github.com/hansonyu183/zerp/blob/bf0e6e8d81f025bba81612c0e37b1527b2889eee/docs/use-cases/list-navigation.md)。

## 导航、图标与操作文案

- 侧栏不显示“导航”标题。已知领域、资源和操作采用有业务含义的统一语义图标；同一意图使用同一图标，不同或反向意图可区分。
- 有子项的导航分组默认收起，由用户点击展开；没有子项的一级入口直接导航。
- 普通操作保留准确的短中文，图标辅助识别。桌面行操作只显示图标，中文名称用于无障碍标签、悬停和键盘聚焦提示；手机行操作采用图标加短文字，不依赖悬停提示。手机根据可用宽度保留常用操作，其余收入“更多”，桌面保留前三项及更多菜单。
- 菜单切换按钮保留无障碍名称，不显示提示浮层。未知语义的动态导航项没有图标时保留文本。
- 页面及明细的新增按钮、图标提示和新增弹窗标题统一为“新增”，不拼接实体名；成功提示使用“新增成功”等自然表述。多个新增入口通过所属区块区分。
- 查询、保存、提交、克隆、删除、移除和附件上传保留各自语义，不能为统一文案而混用。
- 手机选择导航后关闭抽屉，桌面侧栏可收起。正常链接保留修饰键及新标签行为。

来源：[ZERP 公共列表与导航](https://github.com/hansonyu183/zerp/blob/bf0e6e8d81f025bba81612c0e37b1527b2889eee/docs/use-cases/list-navigation.md)、[公共字段与录入](https://github.com/hansonyu183/zerp/blob/bf0e6e8d81f025bba81612c0e37b1527b2889eee/docs/use-cases/field-entry.md)、[Material 规格 #49](https://github.com/hansonyu183/zerp-ui/issues/49)，以及 oit-go `README.md` 的“当前页面与导航”。

导航分组默认收起为 2026-11-04 用户补充要求；此项记录目标行为，实施与验收仍通过 GitHub Issues 跟踪。

## 手机端列表

- 桌面端列表采用表格行，手机端切换为逐条记录的卡片呈现。
- 卡片保留字段名称与对应值、记录身份、选择能力及获准的行操作，保持原有查询、分页、权限和业务语义。
- 卡片首行左侧放复选框、右侧放行操作，字段位于下方；单侧缺省时另一侧保持原位。列表顶部显示“全选当前页”和当前页已选数量，保留半选和禁用语义。
- 卡片排版由库统一负责，不要求消费者另外提供手机端模板。

来源：2026-11-04 用户补充要求。此项及本轮修复的实施与验收通过 [#71](https://github.com/hansonyu183/zerp-ui/issues/71) 跟踪。

## 业务文案与操作上下文

- 导航、标题、字段、按钮、提示及错误消息均简洁、业务导向，使用用户熟悉的业务名称。
- 上下文已有明确分类时省略重复类别词，例如“客户资料”写作“客户”；同一功能的导航与页面名称保持一致。
- 说明只保留帮助用户完成操作、判断结果或理解业务风险的内容。实现机制、开发进度、核实状态及内部技术细节留在文档和日志；需要用户处理的未知结果及恢复入口仍按前述规则持续呈现。
- 必要提示直接说明业务影响及下一步，保留单位、校验要求、未保存、提交结果不确定和不可逆操作等关键含义。
- 新增或修改界面时，逐项检查受影响的可见文案。
- 报表下钻返回保留未提交条件、结果、页码及滚动位置；恢复时仍核验当前结果资格，过期需重新查询。

## 使用边界

以上要求用于本库拥有的呈现与交互；业务名称、导航资格、请求、Session、Router 和结果有效性事实继续由消费者提供。OIT 的工作台入口、报表分组及单据菜单组织属于应用自己的导航，不固化到通用库。

精度、权限、未知写入锁和迟到响应隔离继续遵循既有交互契约。本文不据此推定已完成实现或真实应用验收，也不增加新的公开 API。当前没有足够依据指定个人偏爱的品牌色、特定字体或特别紧凑的密度。

2026-11-04 手机卡片首行与图标短文字要求经用户确认，实施见 [#74](https://github.com/hansonyu183/zerp-ui/issues/74)。
