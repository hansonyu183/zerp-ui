# UI 细节判断与交付清单

2026-11-16 按用户明确要求修订，来源见 [规范 UI-GOV-06](ui-preferences.md)及 [#158](https://github.com/hansonyu183/zerp-ui/issues/158)。文案与常规 UI 细节由 Agent 按现有要求完成判断、开发与审查，不逐项询问用户。

下表保留 Q1–Q5 引用，作为开发判断提示，不是待用户逐项审批的问卷。此前提出的字段数、间距范围、候选视口或消息高度比例均未成为已确认的全局验收阈值，不能自动写成强制规范。已有明确字号、尺寸、列数及操作数上限继续执行。

| 项 | 对应条款 | 常规处理方式 |
| --- | --- | --- |
| Q1 响应式与短表单 | THEME-06、MOBILE-01、FORM-03 | Agent 按容器宽度、字段内容与已有响应式能力确定排布和定向样本，遵守筛选/编辑列数上限及短表单单列要求；不要求用户逐页指定断点或字段数阈值。 |
| Q2 留白与间距 | THEME-06、FORM-03/04 | Agent 沿用紧凑密度、公共样式与 Material 呈现，判断字段、卡片和 Tab 的合理间距，检查标签不重叠；不逐个间距询问用户。 |
| Q3 内容宽度及溢出 | DESKTOP-01、MOBILE-01/02、ACTION-01 | Agent 选择代表性宽度与长值验证样本，保留桌面完整字段、手机流式卡片及无横向溢出，按现有约束处理次要操作收纳；不把测试样本当成新断点规范。 |
| Q4 操作层级 | THEME-04、ACTION-01/02 | Agent 复用已有 Vuetify 语义样式，保持主要、普通、危险操作可区分及名称一致；不重复征询常规颜色、变体或图标细节。 |
| Q5 文案与长反馈 | SHELL-05、WORK-02/03 | Agent 结合业务语境审查文案，统一名称、删去重复及实现细节，保留错误影响和下一步；不设统一字数上限。长反馈在限定区域内滚动，区域大小由 Agent 按可用空间与稳定布局要求判断。 |

仅当业务含义不明确或需要改变已确认要求时保留未决项。完成其余明确且已授权的开发后，随交付只留一份合并清单，说明问题、影响、建议及尚未实施或待定的部分；开发中不反复提问，不擅自补造业务含义或修改要求，也不把待定部分算作已完成。没有此类未决项时无需确认清单。

浏览器子像素测量容差、等待字体与有限动画结束属于验证技术条件，不改变产品要求，也不能据此声称真实手机平台已经验证。
