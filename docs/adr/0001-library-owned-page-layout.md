# 页面与领域区块的布局归库

正式规格见 [#40](https://github.com/hansonyu183/zerp-ui/issues/40)。本记录保留架构取舍，不维护实施状态。

为保持完整业务页面的统一交互与呈现，页面布局及领域区块内部布局均由 `@zerp/ui` 持有。消费者提供页面类型、数据、Adapter、字段、分组、顺序及业务事实；库决定标题、工具栏、筛选、列表、详情、编辑区域以及区块内部的排布、栅格、间距、折叠和响应式布局。Router 与页面选择仍归消费者。

本决定收窄[实施规格 #7](https://github.com/hansonyu183/zerp-ui/issues/7)、[组件层级 #16](https://github.com/hansonyu183/zerp-ui/issues/16)及[后续设计 #32](https://github.com/hansonyu183/zerp-ui/issues/32)中的消费者布局扩展边界。主内容入口收窄为明确类型的页面；领域区块由库提供，消费者通过有限内容定义表达需求。取舍是消费者需要通过库增加所需区块，换取库对完整页面及局部排版的一致控制。

公开组件入口限定为 `AuthPage` 和 `AppPage`。六类业务 View 及 `DynamicForm`、`ReferencePicker`、`DataList`、`RecordDetails`、`EditGuard`、`VoucherEditor` 等复合交互转为内部实现，消费者通过强类型页面定义提供内容。Adapter、相关类型与必要主题 API 继续公开。此决定同时取代 #16 中允许消费者独立挂载业务 View 和复合交互的公开层级边界。

入口收窄后，完整页面须承接已有的单据编辑与两种办理协议、原内容恢复、独立详情与关联跳转、编辑及离页保护，以及账户资料与改密表单。写入互斥、未知结果锁和身份失效处理继续遵循原交互契约。公司数据、业务规则、请求、凭证、Session 与 Router 仍由消费者持有；示例表单不作为真实账户规则的依据。

## 固定布局约束

- App Bar 固定在视口顶部，不随页面内容滚动。库统一预留其实际高度并管理层级，保证内容和弹层不遮挡顶栏，顶栏也不覆盖其它组件；响应式高度变化同样遵守此约束。菜单、弹窗、遮罩和消息均限制在顶栏下方的可用区域。
- 禁用会改变布局的消息反馈组件。消息的出现、更新或关闭不得推移、挤压页面内容或改变其文档流占位。消息的呈现与关闭不改变业务写入状态；未知结果锁、刷新失败后的只读限制及核实、重试能力继续遵循原交互契约。阻塞状态和恢复入口须持续可达，不能仅依赖自动消失的通知；字段校验反馈同样不得挤动布局。
- App Bar 固定采用 ZERP 的子组件组合与排列：导航开关、可回首页的品牌区（品牌头像、产品名和企业名）、间隔、主题预设菜单、独立明暗切换、头像与账户菜单。账户菜单固定提供名称与头像、更改密码、退出登录；窄屏沿用其文字收起方式，页面标题位于顶栏下方的主内容区。消费者提供品牌、账户和主题事实，不获得子组件插入、替换或排序接口。

App Bar 的只读参考基线为 ZERP `bf0e6e8d81f025bba81612c0e37b1527b2889eee` 的 `frontend/src/target/layouts/AppLayout.vue`。复用的是组件组合及交互；公司数据、业务规则和账户请求仍由消费者提供，ZERP 仓库保持只读。
