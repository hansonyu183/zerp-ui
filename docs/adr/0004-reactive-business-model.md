# 单一响应式业务模型驱动统一界面

正式目标规格见 [#122](https://github.com/hansonyu183/zerp-ui/issues/122)。2026-11-12 用户确认以一个响应式业务模型表达结构、数据及操作，取消消费者另外提供页面定义、资源/报表类别和关系注册表；对象成员直接表达层级，不要求 `properties` 包装。节点类型与固定 operations 决定交互，业务回调、资格及通知属于同一模型，库持有布局、草稿、写入及恢复生命周期。

本决定重新议定 ADR-0001/0002/0003 的公开装配边界：目标公开组件收敛为绑定 model 的 BusinessApplication，原页面工厂及 AuthPage/AppPage 可作为内部深模块复用，不保留旧公开装配的运行时兼容层。代价是消费者和库内示例需要一次破坏性迁移，换取模型与页面不再重复表达同一业务内容；有限操作及精确类型契约继续保留，不开放任意命令、组件或状态机配置。

初版权限通过消费者裁剪节点和操作表达。此决定已由 [#148](https://github.com/hansonyu183/zerp-ui/issues/148) 修订：消费者提供完整模型和归属当前 owner 的根级 userPermissions，由UI统一裁剪；readOnly、disabledReason及操作存在性继续表达业务限制。普通用户的独立业务边界默认拒绝，边界内字段继承并只能收窄，操作缺省拒绝，管理员不能覆盖业务限制。引用采用完整目录按需缓存下拉，导航采用模型内显式有序分组投影，认证与业务复用品牌和主题，实施及正式交付见 [#149](https://github.com/hansonyu183/zerp-ui/issues/149)。操作反馈和主动通知统一呈现，关闭消息不能解除未知结果锁。所属层级、值数组/独立集合、独立对象操作及引用类型确定关系和保存边界，临时撤权不能合并事务或删除原请求证据。API、业务规则、Session、Router、加密及耐久存储仍由消费者提供，跨资源联锁仍由权威业务事实决定。

本源码按 #123–#125 实施此决定，具体契约以 #122 为准，正式发行证据见 #125；0.31.1 的历史发行仍使用旧入口。库独立验收并发布后才实施独立 oit-go 接入，原 ZERP 保持只读；#106 的纯 API 驱动设计继续暂停。

## #152 / #154 修订：直接业务模型与宿主统一迁移

[#152](https://github.com/hansonyu183/zerp-ui/issues/152) 与 [#154](https://github.com/hansonyu183/zerp-ui/issues/154) 取代上文中前端草稿、冻结请求、耐久原请求及普通离开确认的目标决定。唯一公开模型为直接定义的 BusinessModel，元数据使用 modelMetadata Symbol；公开宿主统一消费此契约，不保留旧工厂或运行时兼容分支。输入直接更新模型 value，操作读取当前模型；冲突、请求有效性、未知结果恢复属于消费者业务回调和后端。

聚合按结构及有序投影展示对象和集合，不按业务名猜测内容，不自动跳到第一个集合，不把子集合扩展为全局导航。权限仍来自根级 owner 对应的 userPermissions，显式导航、按需候选和统一认证外壳沿用 #148。纯类型示例与可运行合成消费者分开，正式包、CI 和真实产品接入分别验收；历史发行证据保持原义。

## 2026-11-15 修订：静态对象与权限裁剪

用户确认 oit-go 直接定义完整静态响应式对象，登录时后端返回用户权限，UI 根据权限调整组件或直接裁剪、调整传入对象。当前接口及验收约束统一见 [#152「2026-11-15 接口修订」](https://github.com/hansonyu183/zerp-ui/issues/152)。本修订补充结构定义来源，并取代早期要求永久保留完整传入对象的限制；历史验收不作为本修订的符合证据。

同日用户补充确认传入时机与登出生命周期，统一维护于 #152 的“传入时机、登出与再次登录”：登录前传入、根对象身份保持、登出清理与迟到响应隔离，以及直接裁剪节点后的结构恢复均属验收范围。

同日用户要求收紧类型，取代早期以任意业务成员名为由使用 Symbol 元数据的接口决定；当前目标见 #152“固定类型与属性边界”。公开类型、宿主及示例尚须统一迁移，历史 Symbol 契约不作为新目标的符合证据。

## 2026-11-16 修订：统一对象、独立集合及所属明细

用户确认将单据整合到 ObjectNode，通过 family/type 表达差异；独立集合统一使用 Collection，不再定义 VoucherNode/VoucherCollection。ObjectNode 的有序 members 数组取代 form；Collection 不属于节点，RecordsNode 表达随父保存的明细；全局导航仅指向根级集合。字段采用可空 label、Operation 使用必需 disabled，引用只负责候选选值；格式、强类型 JSON 自动打印及独立工作台一并纳入目标。

本决定取代早期目标中的 Symbol、对象 form、集合 element/list/query 及独立记录导航约定。正式规格见 [#152](https://github.com/hansonyu183/zerp-ui/issues/152)，完整声明及合成示例见 [接口工件](../interfaces/README.md)。本轮只完成接口工件与编译验收，未迁移公开包或宿主；旧实现仅是现行运行时，不增加双契约兼容入口。

## #159 实施：唯一静态模型与有限能力保留

本节记录 0.44.0 的实施边界。领域分组采用下文 2026-11-17 修订，当前发行及接入入口见[项目说明](../../README.md)。

[#159](https://github.com/hansonyu183/zerp-ui/issues/159) 将上述目标落实到唯一公开声明及宿主：固定普通属性取代 Symbol，根 members 只包含 Collection，对象与单据共用 ObjectNode，所属明细使用 RecordsNode。类型源统一为 src/model/business-model.ts，由 @zerp/ui/model 仅以类型导出；临时目标声明副本删除。私有旧页面/运行时只供既有回归，不参与新模型检测、转换或 fallback。

本次采用保留完整静态结构、按权限裁剪组件的策略；这使撤权后的再次增权和同根对象再次登录可以恢复新获权结构。消费者清理会话业务数据并检查异步回写有效性；库隔离旧 busy、选择、候选呈现与反馈，不持有冻结请求、编辑基线或原请求日志。

既有资料审批、流程、处理、批次、报表、脚本交互及有限输出通过封闭能力补齐，不因新接口暂未表达而删除。对象种类仍只有 standard/voucher；补齐及能力对应见 [迁移清单](../interfaces/static-migration.md) 和 #159 的父规格回写。导航 href/visit 接受 Collection | null，null 专指首页并由消费者同步 Router；记录选中留在所属集合，引用字段不附带维护跳转。

本地候选、独立安装、CI、正式发行与真实产品接入分别验收；具体源码、命令、tgz 摘要及未完成项维护于 #159/#160/#161/#162，不将本 ADR 或历史记录当成验收通过证明。原 ZERP/oit-go 保持只读，不正式发行或连接生产写入。

自动模板打印另使用消费者的 `ObjectNode.printable` 事实确认当前值及所属明细。记录身份不能证明输入已经保存；消费者从有效权威结果派生此事实，未知结果和未保存输入不具备资格。单条及当前页在预览/调用前重检，当前页有未确认的获权记录时不静默漏行。库不为此恢复编辑基线、第二份权威快照或自动查询。必要接口补齐及原因已回写 #152/#159。

## 2026-11-17 修订：领域分组组织独立集合

用户要求保留客户领域下多个并列集合的对象结构，修订上文“根 members 只包含 Collection”及“全局导航仅指向根级集合”的限制。BusinessModel.members 允许 Collection 或 DomainGroup；领域分组固定一层，仅包含独立 Collection，不属于 BusinessNode，不提供整体 query/update，也不成为授权或保存边界。各集合继续独立查询、授权和保存，导航和有限目标引用领域中的原集合；字段分组与 RecordsNode 的随父保存语义不变。

此决定保留模型业务入口的领域归属，同时避免把领域误建为可保存 ObjectNode。导航仍由显式 groups/sections 投影，不增加递归导航配置或独立领域导航目标。领域内容区使用真正的 Material Tabs 切换各独立集合，结构顺序、单/零组处理、按需读取及切换保留上下文沿用 UI 规范。静态结构、会话清理及消费者业务职责沿用现行规则。正式规格及本次验收见 [#152](https://github.com/hansonyu183/zerp-ui/issues/152)，接口及完整客户领域例子见 [接口工件](../interfaces/README.md)；历史发行证据不变。

## 2026-11-18 修订：从业务成员生成侧栏

用户确认侧栏只展示领域，并移除独立导航投影。BusinessCategory 与可选 DomainSection 用成员数组表达层级和顺序，DomainGroup 组织原 Collection。工作台作为已配置应用的独立入口位于侧栏顶部，品牌仍链接首页。路由保持 current、href、visit，消费者继续持有 Router。此修订取代前文显式导航投影的决定。

## 2026-11-23 修订：节点直接表达读取资格

本修订取代根级权限清单及空标签隐藏规则。会话保留状态与 owner。消费者通过节点的 `readable`、`readOnly` 和操作的 `disabled` 更新同一个响应式模型。UI 按当前值呈现，后端负责请求鉴权。接口细节见[静态模型接口](../interfaces/README.md#操作与会话)。

## 2026-11-26 修订：认证与工作区分层

用户确认登录和工作采用独立页面，对应同一根模型的 `authentication` 和 `work`。工作区成员、账户、导航及工作台归 `work`。品牌、主题、会话和消息在应用根共享。唯一公开入口仍为 `BusinessApplication`，消费者持有 Router 和业务回调。见[顶层接口](../interfaces/README.md#应用认证与工作区)。

## 2026-11-27 修订：集合路由与记录窗口

库从源码定义的业务结构管理页面 Router，工作台归首页集合。链接只定位集合页面，查看、编辑和新增在工作区按业务类型复用窗口。窗口的编辑值与最近确认值只用于本次编辑及同类对象切换。消费者继续掌握业务提交、冲突、未知结果及请求有效性。UI 根据当前目标触发可选读取回调，实际数据及回写由消费者管理。见[静态模型接口](../interfaces/README.md)和 [UI 规范](../ui-preferences.md)。

## 2026-11-27 修订：应用组件命名

用户确认将唯一公开组件更名为 `App`。消费者从 `@zerp/ui` 导入 `App`，继续传入同一个 `BusinessModel`。

## 2026-11-28 修订：记录窗口的编辑与读取

窗口直接编辑响应式业务对象，消费者监听字段及所属明细变更。打开或切换同类记录时重新调用已声明的读取回调。读取成功后窗口复制业务值用于未保存比较，保存成功时更新对应范围。确认换记录后，离开的对象保留当前值，返回时由读取回调写回。不同业务类型的窗口各自保有当前记录。见 [UI-FORM-10](../ui-preferences.md) 和[记录窗口接口](../interfaces/README.md#集合路由与记录窗口)。
