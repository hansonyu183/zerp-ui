# 单一响应式业务模型驱动统一界面

正式目标规格见 [#122](https://github.com/hansonyu183/zerp-ui/issues/122)。2026-11-12 用户确认以一个响应式业务模型表达结构、数据及操作，取消消费者另外提供页面定义、资源/报表类别和关系注册表；对象成员直接表达层级，不要求 `properties` 包装。节点类型与固定 operations 决定交互，业务回调、资格及通知属于同一模型，库持有布局、草稿、写入及恢复生命周期。

本决定重新议定 ADR-0001/0002/0003 的公开装配边界：目标公开组件收敛为绑定 model 的 BusinessApplication，原页面工厂及 AuthPage/AppPage 可作为内部深模块复用，不保留旧公开装配的运行时兼容层。代价是消费者和库内示例需要一次破坏性迁移，换取模型与页面不再重复表达同一业务内容；有限操作及精确类型契约继续保留，不开放任意命令、组件或状态机配置。

权限体现为授权节点、字段只读及 operation 的存在/禁用原因；操作反馈和主动通知统一呈现，关闭消息不能解除未知结果锁。所属层级、值数组/独立集合、独立对象操作及引用类型确定关系和保存边界，临时撤权不能合并事务或删除原请求证据。API、业务规则、Session、Router、加密及耐久存储仍由消费者提供，跨资源联锁仍由权威业务事实决定。

本源码按 #123–#125 实施此决定，具体契约以 #122 为准，正式发行证据见 #125；0.31.1 的历史发行仍使用旧入口。库独立验收并发布后才实施独立 oit-go 接入，原 ZERP 保持只读；#106 的纯 API 驱动设计继续暂停。
