# 单一响应式业务模型驱动统一界面

正式目标规格见 [#122](https://github.com/hansonyu183/zerp-ui/issues/122)。2026-11-12 用户确认以一个响应式业务模型表达结构、数据及操作，取消消费者另外提供页面定义、资源/报表类别和关系注册表；对象成员直接表达层级，不要求 `properties` 包装。节点类型与固定 operations 决定交互，业务回调、资格及通知属于同一模型，库持有布局、草稿、写入及恢复生命周期。

本决定重新议定 ADR-0001/0002/0003 的公开装配边界：目标公开组件收敛为绑定 model 的 BusinessApplication，原页面工厂及 AuthPage/AppPage 可作为内部深模块复用，不保留旧公开装配的运行时兼容层。代价是消费者和库内示例需要一次破坏性迁移，换取模型与页面不再重复表达同一业务内容；有限操作及精确类型契约继续保留，不开放任意命令、组件或状态机配置。

初版权限通过消费者裁剪节点和操作表达。此决定已由 [#148](https://github.com/hansonyu183/zerp-ui/issues/148) 修订：消费者提供完整模型和归属当前 owner 的根级 userPermissions，由UI统一裁剪；readOnly、disabledReason及操作存在性继续表达业务限制。普通用户的独立业务边界默认拒绝，边界内字段继承并只能收窄，操作缺省拒绝，管理员不能覆盖业务限制。引用采用完整目录按需缓存下拉，导航采用模型内显式有序分组投影，认证与业务复用品牌和主题，实施及正式交付见 [#149](https://github.com/hansonyu183/zerp-ui/issues/149)。操作反馈和主动通知统一呈现，关闭消息不能解除未知结果锁。所属层级、值数组/独立集合、独立对象操作及引用类型确定关系和保存边界，临时撤权不能合并事务或删除原请求证据。API、业务规则、Session、Router、加密及耐久存储仍由消费者提供，跨资源联锁仍由权威业务事实决定。

本源码按 #123–#125 实施此决定，具体契约以 #122 为准，正式发行证据见 #125；0.31.1 的历史发行仍使用旧入口。库独立验收并发布后才实施独立 oit-go 接入，原 ZERP 保持只读；#106 的纯 API 驱动设计继续暂停。

## #152 / #154 修订：直接业务模型与宿主统一迁移

[#152](https://github.com/hansonyu183/zerp-ui/issues/152) 与 [#154](https://github.com/hansonyu183/zerp-ui/issues/154) 取代上文中前端草稿、冻结请求、耐久原请求及普通离开确认的目标决定。唯一公开模型为直接定义的 BusinessModel，元数据使用 modelMetadata Symbol；公开宿主统一消费此契约，不保留旧工厂或运行时兼容分支。输入直接更新模型 value，操作读取当前模型；冲突、请求有效性、未知结果恢复属于消费者业务回调和后端。

聚合按结构及有序投影展示对象和集合，不按业务名猜测内容，不自动跳到第一个集合，不把子集合扩展为全局导航。权限仍来自根级 owner 对应的 userPermissions，显式导航、按需候选和统一认证外壳沿用 #148。纯类型示例与可运行合成消费者分开，正式包、CI 和真实产品接入分别验收；历史发行证据保持原义。
